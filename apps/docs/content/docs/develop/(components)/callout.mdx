## Usage

```ts copy title="Import"
import {
  Callout,
  CalloutAction,
  CalloutTitle,
  CalloutContent,
} from "@amerfathullah/myds-react/callout";
```

```tsx copy title="Anatomy"
export default () => (
  <Callout>
    <CalloutTitle />
    <CalloutContent />
    <CalloutAction>
      <CalloutClose />
    </CalloutAction>
  </Callout>
);
```

### Dismissible

If the callout is dismissible, you can display a **close button** on the top right corner by declaring the `dismissible` prop.
To capture the dismiss event, you may use the `onDismiss` prop.

Screen readers announce the close button as "Close". Set `closeLabel` to name it in your site's language, for example `closeLabel="Tutup"`.

To dismiss the callout via event listener, simply wrap the target element with `CalloutClose`. `CalloutClose` will also trigger the onDismiss event, if defined.

### Screen readers

Callout renders `role="note"`. Screen readers read it in reading order with the rest of the page, and don't announce it when it appears. That suits a callout in the page content.

When a callout appears after the user acts and must be heard at once, such as an error after a failed submit, pass `role="alert"`.

```tsx copy title="Error after a failed submit"
import { useState, type FormEvent } from "react";
import { Button } from "@amerfathullah/myds-react/button";
import {
  Callout,
  CalloutContent,
  CalloutTitle,
} from "@amerfathullah/myds-react/callout";

export default function ApplicationForm() {
  const [error, setError] = useState(false);

  async function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    const response = await fetch("/api/apply", {
      method: "POST",
      body: new FormData(event.currentTarget),
    });
    setError(!response.ok);
  }

  return (
    <form onSubmit={handleSubmit}>
      {error && (
        <Callout variant="danger" role="alert">
          <CalloutTitle>Your application wasn't sent</CalloutTitle>
          <CalloutContent>Check your details and try again.</CalloutContent>
        </Callout>
      )}
      {/* The form's fields */}
      <Button type="submit">Submit</Button>
    </form>
  );
}
```

The icon and the colour show the Variant, but neither reaches screen readers: Callout hides the icon from them. So the title's words must say the Variant, in your site's language. Either:

- word the title so it says it, as "Your application wasn't sent" does in the example above, or
- start the title with the Variant's name: Information (`info`), Success (`success`), Warning (`warning`) or Error (`danger`). For example `<CalloutTitle>Error: Form not sent</CalloutTitle>`, or `<CalloutTitle>Ralat: Borang tidak dihantar</CalloutTitle>` on a Malay page.

If the design can't show that word, put it in visually hidden text at the start of the title instead: `<span className="sr-only">Error: </span>`. Use it in place of a visible name, never as well as one, or screen readers read the Variant twice.

```tsx copy title="A title that says the Variant"
// The Variant's name, shown
<Callout variant="danger">
  <CalloutTitle>Error: Form not sent</CalloutTitle>
  <CalloutContent>Check your details and try again.</CalloutContent>
</Callout>

// The Variant's name, visually hidden, where the design can't show it
<Callout variant="danger">
  <CalloutTitle>
    <span className="sr-only">Error: </span>Form not sent
  </CalloutTitle>
  <CalloutContent>Check your details and try again.</CalloutContent>
</Callout>
```

This matters most with `role="alert"`. A screen reader reads the callout's text the moment it appears, and a title that doesn't say the Variant leaves the user guessing whether it's an error.
