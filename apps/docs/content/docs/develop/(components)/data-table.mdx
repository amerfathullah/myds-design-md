### Naming the Table

The `<table>` that `DataTable` renders has no name by default. Give each table a name, so screen reader users can tell the tables on a page apart when they move between them or list them.

- **With a visible title:** put a heading above the table, and pass the heading's `id` to `aria-labelledby`. Screen readers announce the table by the heading's text, for example "Senarai pemohon".
- **With no visible title:** pass `aria-label`, for example `aria-label="Senarai pemohon"`. It isn't shown, so use it only when the page shows no title for the table, and set it in your site's language.

If you pass both, `aria-labelledby` wins. Both go to the `<table>` only.

Ids must be unique on the page. A component that renders more than once, like the one in this example, makes its heading's id with `useId()`.

`DataTable` doesn't take a `caption` or children, so it can't render a `TableCaption`. Name the table with a heading and `aria-labelledby` instead.

<Tabs items={["Preview", "Code"]}>
  <Tab value="Preview">
    <div className="not-prose">
      <ApplicantTable />
    </div>
  </Tab>
  <Tab value="Code">
    ```tsx
    import { useId } from "react";
    import {
      DataTable,
      type ColumnDef,
    } from "@amerfathullah/myds-react/data-table";

    type Applicant = {
      id: string;
      name: string;
      reference: string;
      status: string;
    };

    const applicants: Applicant[] = [
      {
        id: "1",
        name: "Aminah binti Yusof",
        reference: "PMH-0142",
        status: "Diluluskan",
      },
      {
        id: "2",
        name: "Ravi a/l Muthu",
        reference: "PMH-0143",
        status: "Dalam semakan",
      },
      { id: "3", name: "Tan Mei Ling", reference: "PMH-0144", status: "Ditolak" },
    ];

    // DataTable makes its header and body cells' ids from the column ids, so the
    // tables on one page need column ids of their own
    const columns: ColumnDef<Applicant>[] = [
      { id: "applicant-name", accessorKey: "name", header: "Nama" },
      {
        id: "applicant-reference",
        accessorKey: "reference",
        header: "No. rujukan",
      },
      { id: "applicant-status", accessorKey: "status", header: "Status" },
    ];

    // The heading above the table names it through `aria-labelledby`. `useId()`
    // gives the heading an id of its own, so the page repeats no id however many
    // times this renders.
    export function ApplicantTable() {
      const headingId = useId();
      return (
        <div className="flex flex-col gap-3">
          {/* Use the heading level your page needs */}
          <h4
            id={headingId}
            className="font-heading text-txt-black-900 text-body-lg font-semibold"
          >
            Senarai pemohon
          </h4>
          <DataTable
            aria-labelledby={headingId}
            columns={columns}
            data={applicants}
          />
        </div>
      );
    }
    ```
  </Tab>
</Tabs>

```tsx

### Expanding Columns

You can expand the size of the cells in a column by setting the `expandable` property to `true` in the `meta` object of the column definition.

To demonstrate this, we have set the `expandable` property to `true` for the `Name` and `Position` columns. You can click on the expand icon to view the full content of the cell.

The expand button always shows in the column's header, at every screen width, so keyboard and touch users can reach it too. Screen readers announce it as "Widen" followed by the text the column's header renders, for example "Widen Name", or as "Widen column" if the header renders no text. Its `aria-pressed` tells them whether the column is widened. Set `widenLabel` in the same `meta` object to name it in your site's language, for example `meta: { expandable: true, widenLabel: "Lebarkan Nama" }`.

### Tooltip on Column Headers

You can add a tooltip to the column headers by setting the `tooltip` property in the `meta` object of the column definition.

To demonstrate this, we have set the `tooltip` property to `Age` and `Position` column. Hover over or focus the question-mark icon in the column header to view the tooltip. The icon's hit area is at least 24×24px, so the pointer doesn't need to land on the 16px icon itself.

Screen readers announce each tooltip's trigger, a question-mark icon, as "Tooltip". Set `tooltipLabel` in the same `meta` object to name it in your site's language, for example `meta: { tooltip: "Umur pekerja", tooltipLabel: "Maklumat" }`.

### Sorting

You can sort the data in the table by setting the `sortable` property to `true` in the `meta` object of the column definition.

To demonstrate this, we have set the `sortable` property to the `Position` column. Click the sort icon to toggle the sorts available.

The sort button always shows in the column's header, at every screen width, so keyboard and touch users can reach it too. It shows only in a column that can sort, one with an `accessorKey` or `accessorFn`. Screen readers announce it as "Sort by" followed by the text the column's header renders, for example "Sort by Position", or as "Sort column" if the header renders no text. Set `sortLabel` in the same `meta` object to name it in your site's language, for example `meta: { sortable: true, sortLabel: "Isih mengikut Jawatan" }`.

A sorted column's header has `aria-sort`, `ascending` or `descending`, so screen readers announce how the table is sorted. When Shift+click sorts by more than one column, only the first sorted column's header has it.

### Row Selection

Enable selection mode by passing a `selection` prop to the `DataTable` component. The `selection` prop accepts an object with the following properties:

- `mode`: The type of selection. Can be either `checkbox` or `radio`.
- `onSelectionChange`: A callback function that is triggered when the selection changes.
- `rowId`: The unique identifier for each row in the table.

          cell: () => {
            return <Button variant="default-outline">Edit</Button>;

        },

      selection={
        {

    ```

  </Tab>

Screen readers announce each row's checkbox or radio as "Select row 1", "Select row 2" and so on. The numbers count the rows the table shows, from top to bottom: expanded sub-rows count, and the numbers follow the current sort. The selection column's header is the visually hidden text "Select". To name these controls in your site's language, add these properties to `selection`:

- `rowLabel`: Names each row's checkbox or radio. Defaults to "Select row N". A function is called with each row and returns its name, for example `` rowLabel: (row) => `Pilih ${row.original.name}` ``. A string names every row's control with that string, so screen reader users can't tell the rows apart; prefer a function that names the row.
- `selectAllLabel`: Names the header's checkbox, which selects every row, in `checkbox` mode. Defaults to "Select all rows". For example, `selectAllLabel: "Pilih semua baris"`.
- `clearLabel`: Names the header's button that clears the selection in `radio` mode. Defaults to "Clear selection". For example, `clearLabel: "Kosongkan pilihan"`.
- `columnLabel`: The selection column's visually hidden header. Defaults to "Select". For example, `columnLabel: "Pilihan"`.

```tsx
<DataTable
  data={data}
  columns={columns}
  selection={{
    id_by: "id",
    mode: "checkbox",
    rowLabel: (row) => `Pilih ${row.original.name}`,
    selectAllLabel: "Pilih semua baris",
    columnLabel: "Pilihan",
  }}
/>
```

In `radio` mode, each table's row radios are one radio group, so the table is one Tab stop: the selected row, or the first row that can be selected while no row is selected or the selected row can no longer be selected. From there, as in any radio group, the arrow keys move to the next or previous row that can be selected and select it, wrapping from the last row to the first, and Space selects the focused row. The arrow keys never leave the table. While a row is selected, the header's "Clear selection" button is a Tab stop of its own, before the rows. It's `type="button"`, so it never submits a form.

Inside a `<form>`, the table submits its selected row's id, the value of its `id_by` key, as `<name>=<row id>`. Nothing is submitted while no row is selected. By default each table generates a name of its own; set `name` in `selection` to give the field the name your form expects. The name must be unique within its form: tables that share one are one radio group, and their selections and radios fall out of step. A row that was selected and then can no longer be selected isn't submitted, because a form never submits a disabled control. `checkbox` mode ignores `name`.

```tsx
<form action="/pegawai/simpan">
  <DataTable
    data={data}
    columns={columns}
    selection={{ id_by: "id", mode: "radio", name: "pegawai" }}
  />
  <Button type="submit">Simpan</Button>
</form>
```

With the row whose `id` is `b` selected, the form submits `pegawai=b`.

### Nested Rows

`DataTable` is also capable of nesting rows. To enable this feature, the following requirements must be met:

1. `data`: Contain a nested array object with a key that matches the `id_by` property in the `nest` object. (eg. `children`)
2. `columns`: Column responsible for expanding & collapsing should pass `Cell.Expand` in the `cell` property.
3. `nest`: An object prop that contains the following properties:
   - `id_by`: The key that matches the nested array object in the `data` property.
   - `expandLabel` (optional): Names each row's expand button. Defaults to "expand row". A string names every button. A function is called with each row and returns its name.

Screen readers announce each row's expand button as "expand row", and its `aria-expanded` tells them whether the row is expanded. Set `expandLabel` to name it in your site's language, for example `expandLabel: "Kembangkan baris"` or `` expandLabel: (row) => `Kembangkan ${row.original.name}` ``.
