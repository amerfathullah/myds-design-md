## Usage

```ts copy title="Import"
import { DateRangePicker } from "@amerfathullah/myds-react/daterange-picker";
import { Label } from "@amerfathullah/myds-react/label";
```

```tsx copy title="Anatomy"
export default () => (
  <>
    <Label id="travel-dates" size="small">
      Travel dates
    </Label>
    <DateRangePicker aria-labelledby="travel-dates" />
  </>
);
```

Name each date range picker. Give a `Label` an `id`, and pass the same id to the picker's `aria-labelledby`, as above. Screen readers then announce each of its two buttons by the label's text, then the prefix and date the button shows: "Travel dates From: 12 Mar 2024" and "Travel dates To: 20 Mar 2024", or "Travel dates From: dd / mm / yyyy" before a date is chosen. The prefixes tell the two buttons apart: "From:" and "To:", "Dari:" and "Hingga:" with `locale="ms"`, or your own `fromLabel` and `toLabel`.

Unlike the date field, a `Label`'s `htmlFor` doesn't work here: the date range picker takes no `id`, and a `Label` whose `htmlFor` matches nothing names nothing, with no error. Clicking the `Label` doesn't open the picker either.

If no visible label names the picker, pass an `aria-label` to name it in your site's language, for example `<DateRangePicker locale="ms" aria-label="Tarikh perjalanan" />`. Screen readers announce it, then each button's prefix and date: "Tarikh perjalanan Dari: 12 Mac 2024". If you pass both, `aria-labelledby` wins. To describe the picker, for example with a hint under its label, pass the hint's id as `aria-describedby`.

### Uncontrolled vs Controlled State

To use the daterange picker in the uncontrolled state, set the `defaultValue` prop to the initial value of the daterange picker.

To use the daterange picker in the controlled state, set the `value` prop to the current value of the daterange picker and provide an `onValueChange` event listener to handle the change.

<Tabs items={["Preview", "Code"]}>
  <Tab value="Preview">
    <div className="not-prose flex flex-col gap-3 items-center">
        <div>
            Uncontrolled
            <DateRangePicker defaultValue={{ from: YESTERDAY, to: TOMORROW }} />
        </div>
        <div>
            Controlled
            <DateRangePicker value={{ from: YESTERDAY, to: TOMORROW }} />
        </div>
    </div>
  </Tab>
  <Tab value="Code">
    ```tsx
    // Uncontrolled state
    <DatePicker defaultValue={{ from: new Date(/* yesterday */), to: new Date(/* tomorrow */) }} />

    // Controlled state
    <DatePicker value={{ from: new Date(/* yesterday */), to: new Date(/* tomorrow */) }} />
    ```

  </Tab>
</Tabs>

### Disabled

There are many ways to interact with DateRangePicker `disabled` state. Daterange picker can be disabled entirely by setting the `disabled` prop to `true`.

For a finer control on which dates to disable, you can pass a `Matcher | Matcher[]` that defines the rules for disabling dates.

<Tabs items={["Preview", "Code"]}>
  <Tab value="Preview">
    <div className="not-prose space-y-2">
      <div className="flex items-center gap-3">
        Disable all dates
        <DateRangePicker defaultValue={DEFAULT_DATERANGE} disabled />
      </div>
      <div className="flex items-center gap-3">
        Disable dates before yesterday
        <DateRangePicker defaultValue={DEFAULT_DATERANGE} disabled={{ before: YESTERDAY }} />
      </div>
      <div className="flex items-center gap-3">
        Disable dates after tomorrow
        <DateRangePicker defaultValue={DEFAULT_DATERANGE} disabled={{ after: TOMORROW }} />
      </div>
      <div className="flex items-center gap-3">
        Disable dates outside of range
        <DateRangePicker
          defaultValue={DEFAULT_DATERANGE}
          disabled={{
            before: new Date().setDate(new Date().getDate() - 1),
            after: new Date().setDate(new Date().getDate() + 1),
          }}
        />
      </div>
      <div className="flex items-center flex-wrap gap-3">
        Disable dates by days of week (eg. Saturday and Sunday)
        <DateRangePicker
          defaultValue={DEFAULT_DATERANGE}
          disabled={{
            dayOfWeek: [0, 6],
          }}
        />
      </div>
      <div className="flex items-center gap-3">
        Disable dates by callback function (eg. disable every 13th of the month)
        <CustomDisableDateRangePicker />
      </div>
    </div>
  </Tab>
  <Tab value="Code">
    ```tsx
    // Disable all dates
    <DateRangePicker defaultValue={{ from: new Date(/* yesterday */), to: new Date(/* tomorrow */) }} disabled />
    
    // Disable dates before yesterday
    <DateRangePicker defaultValue={{ from: new Date(/* yesterday */), to: new Date(/* tomorrow */) }} disabled={{ before: new Date(/* yesterday */) }} />

    // Disable dates after tomorrow
    <DateRangePicker defaultValue={{ from: new Date(/* yesterday */), to: new Date(/* tomorrow */) }} disabled={{ after: new Date(/* tomorrow */) }} />

    // Disable dates outside of range
    <DateRangePicker
      defaultValue={{ from: new Date(/* yesterday */), to: new Date(/* tomorrow */) }}
      disabled={{
        before: new Date().setDate(new Date().getDate() - 1),
        after: new Date().setDate(new Date().getDate() + 1),
      }}
    />

    // Disable dates by days of week (eg. Saturday and Sunday)
    <DateRangePicker
      defaultValue={{ from: new Date(/* yesterday */), to: new Date(/* tomorrow */) }}
      disabled={{
        dayOfWeek: [0, 6],
      }}
    />

    // Disable dates by callback function (eg. disable every 13th of the month)
    <DateRangePicker
      defaultValue={{ from: new Date(/* yesterday */), to: new Date(/* tomorrow */) }}
      disabled={(date) => date.getDate() === 13}
    />
    ```

  </Tab>
</Tabs>

### Locale

To support different locales, you can pass the `locale` prop to the daterange picker.

Default value is `en`. To switch to Bahasa Melayu, pass `ms`.

`locale` also sets what screen readers announce in the From and To calendars: with `ms`, their buttons, grids, weekday headings and days have Malay names. The month view's year buttons are the exception. Screen readers announce them as "Go to the Previous Year" and "Go to the Next Year" unless `previousYearLabel` and `nextYearLabel` rename them in both calendars. Set these in your site's language, for example `previousYearLabel="Pergi ke tahun sebelumnya"` and `nextYearLabel="Pergi ke tahun seterusnya"`.
