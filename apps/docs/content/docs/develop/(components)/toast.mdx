## Usage

### Simple Usage

For simple usage, `AutoToast` can be used directly. It is a pre-assembled, simplified version of the `Toast` that handles common use cases.

```tsx copy title="layout.tsx"
import { AutoToast } from "@amerfathullah/myds-react/toast";

// Put the component high up in the DOM tree
<AutoToast />;
```

```tsx copy title="Anatomy"
"use client";

// Then, publish or emit a new event to the Toast
import { useToast } from "@amerfathullah/myds-react/hooks";

export default () => {
  const { toast } = useToast();
  return (
    <button
      onClick={() => {
        toast({
          variant: "message",
          title: "Hello, world!",
          description: "this is a message toast description",
        });
      }}
    >
      Message
    </button>
  );
};
```

Screen readers announce each toast's close button as "Close". Set `closeLabel` to name it in your site's language, for example `<AutoToast closeLabel="Tutup" />`.

Screen readers announce the region that holds the toasts as "Notifications (F8)", and say "Notification" before each toast's text. Set `viewportLabel` and `announceLabel` to name them in your site's language, for example `<AutoToast viewportLabel="Pemberitahuan ({hotkey})" announceLabel="Pemberitahuan" />`. `{hotkey}` becomes F8, the key that moves focus to the toasts. Don't pass an empty `announceLabel`: Radix logs an error.

### Advanced Usage

Instead of using `AutoToast`, the `Toast` component can be assembled manually for more control.

```tsx copy
"use client";

import { useEffect } from "react";
import { useToast } from "@amerfathullah/myds-react/hooks";
import {
  ToastClose,
  ToastDescription,
  ToastIcon,
  ToastProgress,
  ToastProvider,
  ToastRoot,
  ToastTitle,
  ToastViewport,
} from "@amerfathullah/myds-react/toast";

// Mount the toaster once in your app, high up the tree, in place of AutoToast
export default function Toaster() {
  const { toasts, subscribe, unsubscribe } = useToast();

  // Show each toast that toast() from useToast publishes
  useEffect(() => {
    subscribe();
    return () => {
      unsubscribe();
    };
  }, []);

  return (
    <ToastProvider>
      {toasts.map((event, index) => (
        <ToastRoot
          key={index}
          variant={event.variant || "message"}
          type={event.type}
        >
          <ToastIcon />
          <div className="space-y-1">
            <ToastTitle>{event.title}</ToastTitle>
            {event.description && (
              <ToastDescription>{event.description}</ToastDescription>
            )}
          </div>
          <ToastClose />
          <ToastProgress />
        </ToastRoot>
      ))}

      <ToastViewport />
    </ToastProvider>
  );
}
```

Screen readers announce `ToastClose` as "Close". Pass an `aria-label` to name it in your site's language, for example `<ToastClose aria-label="Tutup" />`.

## Examples

### Variant

5 variants of toast are availablle: `message`, `info`, `success`, `warning` and `error`. The examples of use cases are:

1. `success` variant can be used to indicates a successful action such as creating a new request or submitting a form.
2. `warning` variant can alert the users to take notice, often used for reminders or actions that require attention, such as reporting spam.
3. `information` variant can provides additional details to keep user informed.
4. `error` variant can be used to notify the user of an error that requires resolution before proceeding.

### Screen readers

By default, only an `error` toast interrupts the screen reader. A toast of every other Variant is announced at the next pause, such as the end of the sentence the screen reader is reading.

A toast's `type` sets this: `"foreground"` interrupts, and `"background"` waits for a pause. Without a `type`, an `error` toast is `"foreground"`, and every other Variant is `"background"`. `type` isn't the design guideline's Type, which is `variant`.

When a toast of another Variant must be heard at once, pass `type: "foreground"` to `toast()`. For an error that can wait, pass `type: "background"`.

```tsx copy title="Warning that must be heard at once"
"use client";

import { useEffect } from "react";
import { useToast } from "@amerfathullah/myds-react/hooks";

// Warns the user a minute before the session ends. endsAt is a timestamp in
// milliseconds, like the one Date.now() returns.
export default function SessionWarning({ endsAt }: { endsAt: number }) {
  const { toast } = useToast();

  useEffect(() => {
    const timer = setTimeout(
      () =>
        toast({
          variant: "warning",
          title: "Warning: Your session is about to end",
          description: "Save your work. You'll be signed out in a minute.",
          type: "foreground",
        }),
      endsAt - Date.now() - 60 * 1000,
    );
    return () => clearTimeout(timer);
  }, [endsAt]);

  return null;
}
```

`AutoToast` takes `type` too, and sets it for every toast, whatever its Variant. A toast's own `type`, passed to `toast()`, wins. Prefer setting `type` on the one toast that needs it: with `<AutoToast type="foreground" />`, every toast interrupts, and toasts shown together can interrupt each other.

`ToastRoot` takes `type` as well, for example `<ToastRoot variant="warning" type="foreground">`. In a toaster you assemble yourself, pass each event's `type` to its `ToastRoot`, as the [Advanced Usage](#advanced-usage) toaster does. Otherwise a `type` passed to `toast()` has no effect.

Avoid showing two `error` toasts at once: each can interrupt the other.

### ToastProvider
`ToastProvider` is abstracted from Radix UI's `ToastProvider`. Please refer to the API references in this [documentation](https://www.radix-ui.com/primitives/docs/components/toast#provider).

Its `label` sets what screen readers announce before each toast's text, "Notification" by default. Set it in your site's language, for example `<ToastProvider label="Pemberitahuan">`. Don't pass an empty one: Radix logs an error.

### ToastViewport
`ToastViewport` is abstracted from Radix UI's `ToastViewport`. Please refer to the API references in this [documentation](https://www.radix-ui.com/primitives/docs/components/toast#viewport).

Its `label` names the region that holds the toasts, `Notifications ({hotkey})` by default, where `{hotkey}` becomes F8. Set it in your site's language, for example `<ToastViewport label="Pemberitahuan ({hotkey})" />`. An `aria-label` on `ToastViewport` lands on the list inside the region instead, so it doesn't rename the region.

### ToastIcon
`ToastIcon` draws the toast's 20px status icon in the variant's colour. Render it inside `ToastRoot`, which gives it its variant. It draws no icon for `message`, and renders nothing outside a `ToastRoot`.

It is hidden from assistive technology (`aria-hidden="true"`), because the toast's title carries its meaning. It takes a `<div>`'s props, apart from `children`, and a `className` goes on that `<div>`, around the icon.

### ToastTitle
`ToastTitle` is abstracted from Radix UI's `ToastTitle`. Please refer to the API references in this [documentation](https://www.radix-ui.com/primitives/docs/components/toast#title).

### ToastDescription
`ToastDescription` is abstracted from Radix UI's `ToastDescription`. Please refer to the API references in this [documentation](https://www.radix-ui.com/primitives/docs/components/toast#description).


### ToastClose
`ToastClose` is abstracted from Radix UI's `ToastClose`. Please refer to the API references in this [documentation](https://www.radix-ui.com/primitives/docs/components/toast#close).

Its accessible name is "Close" by default. Pass an `aria-label` to replace it, for example `aria-label="Tutup"`. It always shows a cross icon and ignores `children`, so name it with `aria-label`.

### ToastProgress
`ToastProgress` draws the 4px countdown bar along the toast's bottom edge, filled in the variant's colour. Render it inside `ToastRoot`, which gives it its variant and its duration: the bar shrinks to nothing over `ToastRoot`'s `duration` (default 5000ms), and pauses while the pointer is over the toast. Outside a `ToastRoot` it draws the `message` bar over 5000ms.

It is hidden from assistive technology (`aria-hidden="true"`), because the toast's title carries its meaning. It takes a `<div>`'s props, apart from `children`. A `className` adds to the bar's own classes, and a `style` to its animation duration.
