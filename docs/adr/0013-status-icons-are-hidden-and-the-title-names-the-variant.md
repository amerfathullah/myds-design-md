# Status icons are hidden, and the title names the Variant

Callout, AlertDialog and Toast each draw a status icon chosen by their Variant: a tick in a circle for `success`, an exclamation mark in a circle for `warning`, an "i" for `info`, and a triangle (Callout, Toast) or a diamond (AlertDialog) for `danger` (Toast's `error`). The icon and the colour are the only places the Variant shows. Neither reaches a screen reader: an `<svg>` with no name is an image that says nothing, so a screen-reader user isn't told whether a callout is an error or a success (#197). AutoToast's status icon has been hidden since #79, because the toast's title carries its meaning, and ToastIcon, exported in #172, keeps it hidden. So every status icon the component library draws by Variant is hidden from assistive technology (`aria-hidden="true"`) and never named. The author's title says which Variant it is, in the site's language. It can do that by its wording, such as "Permohonan anda tidak dihantar", or by starting with the Variant's name, such as "Ralat: Borang tidak dihantar". The docs (EN, MS), DESIGN.md and the examples ask for this, and no example is titled with a placeholder such as "Title". Callout follows this rule in #197. AlertDialog's status icon is hidden under it too, in #388. #388 also decides how an alert dialog says its Variant, because its title is often a question and the design guideline calls its `danger` alert Destructive, not Error. If #388 lets the description say it, this ADR is amended.

## Considered Options

- **A Variant label prop with English defaults** ("Success", "Warning", "Information", "Error"), rendered as visually hidden text before the title or as the icon's name: rejected. ADR-0008 gives English defaults to controls with no text of their own, because an English name is better than none. A callout or an alert dialog is meant to have the author's title, and the docs ask for one, so a default would only put an English word in front of it:
  - "Error Permohonan anda tidak dihantar" on a Malay page, read in the Malay voice;
  - "Information" before every callout that leaves `variant` out;
  - the Variant said twice for every author whose title already says it, unless each one knew to switch the default off.

  Malay words would need the `locale` prop that ADR-0008 rejects as the general rule, or the labels context it defers.
- **Naming the icon** (`role="img"` with an `aria-label`), even with words the author sets: rejected. No component in the library names an icon. In the accessibility tree the name is a separate image before the title (`img "Error"`, then the `term`). And the word reaches only screen-reader users, while a word in the title also reaches sighted users who can't tell the icons or colours apart.
- **Leaving the icon exposed with no name**: rejected. An image that is neither named nor hidden fails WCAG 1.1.1, and it tells a user nothing.
- **An opt-in Variant label, with no default**: not needed while the title does the job. It can be added later without breaking anything, as visually hidden text at the start of the title, with its words set by the author or by the labels context ADR-0008 defers, for Callout, AlertDialog and Toast at once.

## Consequences

- Nothing checks that a callout has a title, or that its title says the Variant. A callout titled "Notis" still doesn't tell a screen-reader user whether it is an error or a success.
- Where a design can't show the Variant's name, the author can put it in visually hidden text at the start of the title, such as `<span className="sr-only">Ralat: </span>`. That replaces a visible name; it is never added on top of one.
- Callout and AlertDialog put `aria-hidden` on the status icon's `<svg>`, and ToastIcon already hides the `<div>` around its icon. The shared icon components don't change, so an icon an author imports renders as before. A cross inside a named close button is decoration too: Callout hides its own in #197, as Pill does. Dialog's and AlertDialog's are left to #388.
- Hiding an icon adds no prop and changes nothing visible, so its changeset is a patch for `@amerfathullah/myds-react`, as DateField's hidden calendar icon's was. ADR-0009, ADR-0010 and ADR-0012 shipped as minor releases with unchanged props, because each changed what users meet (whether the banner keeps Tab inside it, whether a callout is announced, which text is cut) and the role or layout that tests and CSS select. Hiding an image that had no name changes neither: screen readers stop reading an empty image, and only a test that looks for that image must change. The changeset tells authors to make each title say its Variant, and to update tests that look for an image inside the component.
